# Engineering Conventions

## Repository rules

- One Spring Boot application per directory under `backend/services/`. A service talks to another
  service **only** through its REST API (`/api/v1/**` public, `/internal/v1/**` service-to-service)
  or Kafka events. No service holds credentials for another service's database, keyspace or Redis
  key space.
- Shared code is limited to `backend/platform/contracts` (event envelope, topic names, payload
  records, JSON schemas) and `backend/platform/service-support` (security wiring, correlation IDs,
  problem details, PostgreSQL outbox, Kafka helpers). **No business logic in shared modules.**
- Secrets only come from the environment / `./secrets` (generated by `scripts/gen-secrets.sh`).
  Nothing secret is committed; `.env.example` holds placeholders only.

## Java

- Java 21, Spring Boot 4.0, package `com.securechat.<service>`; records for DTOs/events.
- Formatting: `.editorconfig` (4 spaces, 120 columns). Imports: no wildcards.
- Constructor injection only; no field injection.
- Validation with Jakarta Bean Validation at API boundaries; errors are RFC 9457 problem details
  with a stable `code` (`ApiException`).
- Time: `java.time.Instant`, UTC everywhere; IDs are UUIDs (UUIDv7 for time-ordered message IDs).
- Logging: structured JSON (ECS) to stdout. **Never log** plaintext, ciphertext, key material,
  passwords, tokens or full request bodies. Log identifiers (message/device/user IDs) only at
  `INFO` or below, with the correlation ID in MDC (`correlationId`) and trace IDs from Micrometer.
- Metrics: Micrometer; labels must be bounded (never `message_id`, `user_id`, `device_id`).

## Tests

| Kind | Naming | Runner | Dependencies |
|---|---|---|---|
| Unit | `*Test.java` | surefire (`mvn test`) | none |
| Integration | `*IT.java` | failsafe (`mvn verify`) | real Postgres/Cassandra/Kafka/Redis via Testcontainers |
| Contract | `contracts` module `*Test.java` | surefire | JSON schemas |
| Frontend | `src/**/*.test.ts` | Vitest | in-memory key store |
| System | `tests/system` | Node + running Compose stack | full stack |
| Failure injection | `tests/failure` | bash + Node | full stack, `docker compose stop/kill` |

Rules: tests must not depend on each other's state; integration tests use unique IDs per test;
nothing is reported as passing unless it was executed (record the command and its output in the PR).

## Commands

```bash
# Backend (from backend/)
mvn -q test                      # unit + contract tests
mvn verify                       # + integration tests (needs Docker)
mvn -pl services/auth-service -am verify   # one service

# Frontends
cd frontend && npm ci && npm test && npm run build
cd admin-portal && npm ci && npm run build

# Stack
scripts/setup.sh                 # one click: secrets → build → start → health → logins
set -a && . ./.env && set +a      # system tests read service credentials from .env
cd frontend && npx tsx system/e2e.ts   # end-to-end system test against the running stack
```
